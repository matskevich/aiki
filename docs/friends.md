# friends early access

aiki is one product. `aiki-friends` is its private early-access and feedback
channel; public `aiki` is the curated stable channel. implementation changes
remain in the owning sources. friends do not need a second development fork.

## start from what already works

keep accepted public skills and working local integrations. changing the delivery
channel does not invalidate previous acceptance. choose one next useful outcome,
then establish what is actually available for that outcome:

| available material | useful next step | claim to avoid |
| --- | --- | --- |
| portable skill | load it and try its focused scenario | a skill installs the maintainer's runtime |
| packaged provider and recipe | install on your own accounts and verify the result | access to the maintainer's account |
| contract for a private runtime | explicitly choose to build or connect your own implementation | installing the maintainer's implementation |
| private implementation without a release | retain the packaging request at its source | another contract makes that code available |

if the recipient asks to use the actual maintained component, record that request
and resolve its packaging/access boundary. do not silently turn it into an
unbounded series of instructions for rebuilding the whole system themselves.
a recipient may deliberately choose their own implementation; preserve that choice.

## feedback and updates

bring an outcome, the failure or unexpected behavior, and a minimal reproducible
example when available. feedback may stay in the existing dialogue; the maintainer
can turn it into a sanitized issue without asking for a second report. never paste
credentials, private transcripts or another person's data into an issue.

connect issue, owning source change, delivery version and the recipient's next
comparable outcome. an issue acknowledgement is not a fix. preview may carry
unfinished reusable experiments with clear limitations; stable promotion requires
the scenario, license and privacy checks. do not invent a response-time promise
or claim automatic issue handling before a consumer has actually been accepted.

## access and current boundary

verify admitted recipients can read the exact private repository before sending
them there as the main entry. use read roles and issues, without source write or
production access. an owner-only seed, a renamed repository and a public map do
not prove usable friends access. see `CURRENT.md` at the repository root for the
actual delivery boundary. public-only users can continue using their accepted
public release while early access is being prepared.
