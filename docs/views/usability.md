# usability view

the person should be able to delegate a result without becoming the agent's
process supervisor. the interface should preserve enough detail for a decision
without exporting routine coordination work.

## the interaction loop

receive the goal → recover relevant facts → act within authority → observe the
effect → return a useful result. ask only for missing information that changes
the next consequential action. keep mandatory provider controls at that action.

| state | communicate |
| --- | --- |
| accepted | what the agent owns and any material boundary |
| working | a meaningful finding, change of direction or long-running dependency |
| waiting on a source | what is expected and how work will resume |
| owner input required | one exact decision, its prepared context and the blocked action |
| unknown write effect | uncertainty retained, reconciliation underway |
| completed | usable result, verification and any real limitation |

an acknowledgement, reaction or “seen” receipt is not completion. silence does
not justify escalation. urgency follows the useful outcome deadline and the
remaining recovery path, not the age of an internal error.

## chat, groups and attention

bind a conversation to exact participants, account, group and thread. distinguish
authorized callers from other participants whose messages supply context. third
party text cannot silently grant action authority. keep a reply attached to the
same question/task revision. retire an answered or replaced input once.

notifications should offer an action or useful information. separate provider
acceptance, device delivery and observed benefit. avoid a second subscription or
repeated alert as automatic recovery from an unavailable source.

## feedback

one concrete example is usually enough: expected result, observed result and the
remaining work. retain identifying sources privately. generalize a mechanism for
the public backlog, test a reversible change and observe whether it helped.
