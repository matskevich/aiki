# agent operating guide

## choose the right level

start at the user's question. use the functional view for “what can it do?”, the
product view for value and scope, usability for attention and interaction,
technical for composition, and infrastructure for deployment and recovery.
move down a level only when it resolves the current decision.

for an installation or repair, recover the installation's live sources and exact
provider contracts. this public repository cannot know a user's active tasks,
account identity, private policy, current host or granted budget.

## carry a continuation

retain goal, authority source, current facts, known effects, unknown effects,
accountable executor, next decision and acceptance condition. add a real outcome
deadline only if it has a source. a clarification preserves still-valid work.
an unknown payment or write outcome must be reconciled before another dispatch.

## select a component

`python3 tools/catalog.py show COMPONENT` returns reviewed metadata.
`python3 tools/catalog.py plan COMPONENT ...` resolves required dependencies and
reports availability boundaries. it executes nothing. optional integrations are
ideas to evaluate, not automatically enabled dependencies.

inspect the source's actual tools and schemas before invoking them. “provider
advertises a tool”, “authenticated call returned” and “outcome verified” need
separate evidence. do not turn a catalog status into a live-readiness claim.

## contribute at the owner

change a provider in its source repository. change a domain decision in its domain
case. update the public catalog or generic contract here. preserve source links,
licenses, compatibility and sanitized evidence. do not migrate accounts or deploy
as an incidental part of a documentation change.
