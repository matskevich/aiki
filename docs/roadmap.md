# roadmap

## current slice

public name and system map, five architecture views, agent navigation, component
metadata, portable contracts and a read-only planner. this is an inspectable
starting point for adoption and contribution.

## next accepted outcomes

1. one independent installation of an available component, with a sanitized
   receipt for useful operation, restart, upgrade and rollback;
2. a clean public export of a selected private implementation, after ownership,
   license, dependencies and historical-data review;
3. one accepted composition across two components, including lost-response
   recovery and exact task/operation identity;
4. versioned compatibility and release manifests derived from those outcomes;
5. better setup and explanation based on optional, source-backed user feedback.

choose the next component from a real person's useful scenario. browser reading
is a compact candidate because an existing implementation has a foreground entry
point. orchestration, attention and payments have more installation-specific
dependencies. this ordering is a hypothesis to test, not a claim of readiness.

private repository synchronization and personal deployment repair stay in their
own cases. publish only generalized lessons, never a public backlog of private
obligations or a recurring model audit of unchanged waits.
