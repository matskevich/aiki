# agent entry

read `README.md`, then `docs/status.md`. select one relevant view and the named
component in `registry/components.json`. do not load every source repository or
the entire private archive to answer a local question.

## route by intent

| request | sources | acceptance |
| --- | --- | --- |
| explain what a person can do | functional and product views | a concrete outcome and its limits |
| compare or design mechanisms | technical view and component contracts | ownership, alternatives and tradeoffs |
| improve the experience | usability view and source-bound feedback | less user effort for the same accepted result |
| install a component | adoption guide and that provider's recipe | useful authorized operation, restart and readback |
| operate or repair a service | infrastructure view and installation-local receipts | intended consumer works through its real launcher |
| change code | the owning source repository's instructions | scoped checks and source/deployment/consumer evidence |

aiki owns the common map, generic contracts, dependency metadata and public
adoption material. provider implementations remain in their source repositories.
do not copy a provider here to avoid its review or release process. when a source
is private or unavailable, preserve that boundary instead of inventing an api or
claiming an installation.

## operating rules

- recover the goal, current facts, authority, existing executor and uncertain
  effects before acting. do not duplicate an active task or payment.
- distinguish description, comparison, preparation, installation and live
  operation. a question about the architecture is not an installation request.
- distinguish source visibility, packaging, authorization, deployment, invocation,
  data freshness and observed outcome. use `unknown` or `not_verified` honestly.
- a skill or discovery record grants no permission. enforce account and target
  binding, provider confirmations and independent readback at the actual action.
- keep personal context and feedback in their private originating cases. export
  only reviewed general mechanisms and synthetic examples.
- keep state ownership explicit. domain records remain in their domain. linear
  is a projection where configured, not a second independent task executor.
- follow existing working routes and credential runtimes. never copy someone
  else's sessions or place resolved secrets in files, examples, logs or git.
- use a separate branch, a scoped diff and a pull request. preserve other work.
  validate the catalog and local links with `python3 tools/catalog.py check`.
- human-facing prose is lowercase. preserve functional case in paths, commands,
  ids, urls and exact quotations.

the public repository contains no owner task queue, private deployment inventory
or cross-device credential configuration. an agent in an actual installation
must recover those from that installation's authorized sources.

for development and learning, read `docs/development-model.md`. distinguish
personal preferences from transferable mechanisms. raw evidence stays with its
owner. development and public promotion are separate code lanes, with a personal
profile rather than another implementation fork. lab access and weekly promotion
remain proposed until their actual setup is accepted.
